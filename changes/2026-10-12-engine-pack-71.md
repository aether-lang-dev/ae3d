### A model's settings reach its parts, a menu can read the engine back, and objects can name each other

- **A model_set_* material setting reaches every part of a model loaded
  with its own materials** (#754). An OBJ with an .mtl draws each part
  with the part's material, and every setter wrote only the model's own,
  which the parts fall back to only when they have none: embers, glitter,
  diffuse, roughness and the rest were dropped on such a model. The
  setters now write the model's own and each part's
  (`core.model_material_count`, `model_material_at`). On the issue's
  two-material OBJ, both parts take the embers, the diffuse and the
  roughness set on the model (`tests/test_loader.ae`).
- **The engine reports its occlusion, bloom, FXAA and render scale**
  (#751): `engine_ssao`, `engine_bloom`, `engine_fxaa` and
  `engine_render_scale`, beside `engine_taa`. A render scale asked for
  before the window opened was dropped (the setter returned 1.0 and kept
  nothing); it is now kept and applied when the device starts, and the
  getter answers what the device applied (`tests/test_engine_settings.ae`).
- **A component field can name another object** (#507):
  `component.object_field`, read with `get_object` and written with
  `set_object`. The field holds the object's id, so a save writes the
  number and an object destroyed since is not found rather than
  dereferenced. A scene file writes the object by its model's place, as
  it writes a parent, and a load maps it back to the id of the object
  made for it. A save's load sets a reference to none when the object it
  names is gone or was destroyed by the save, and counts it
  (`persist.last_dangling`). The inspector shows the named object with a
  picker of the scene's objects, the agent calls the type `object` and
  lists each object's id. The orbit script circles the object set as its
  centre (`tests/test_persist.ae`, `tests/test_components.ae`, the editor
  drive).
- **A model made in a fixed step is drawn where the step put it** (#753).
  Render interpolation took a model's world at its first move in a step
  as the step before's; one made in the step had none, so it was swept in
  from where it was made: on the issue's repro, a figure put at (40, 0, 20)
  was drawn at (8, 0, 4) on its first frame. Its first record now starts
  where the step leaves it, as a teleport's does
  (`tests/test_interpolation.ae`).
- **What a Vulkan frame's draws cost to bind** (#632): `frame.stats`
  answers the descriptor sets the frame had to write (`set_writes`) and
  the uniform bytes it copied (`uniform_bytes`), and `ae3d_bench` prints
  them. On zombie_street (M1 Pro, 2560x1440) a steady frame writes no
  sets, binds 53 and copies 571,776 bytes for 88 draws, in 0.557 ms of
  CPU against a 37.6 ms scene pass.
