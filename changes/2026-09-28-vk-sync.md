### The Vulkan frame read back without racing the passes around it

- The frame's pass, when no post chain follows it, hands its image to the
  readback's copy (`ae3d.vkreadback`) as well as to the next shader. Its
  external dependency now covers the transfer read, so the copy no longer
  races the pass that wrote the frame (#458, `SYNC-HAZARD-READ-AFTER-WRITE`).
- Every offscreen frame renders into the same image. The readback now
  follows its copy with an execution barrier, so the next frame's first
  pass waits for the copy before writing over it
  (`SYNC-HAZARD-WRITE-AFTER-READ`). Two frames drawn before either was read
  raced here, as the overlay's resize check does.
- A cached descriptor set names three images: its colour, its normal map
  and its pose bank or scene depth. Destroying a texture now frees every
  set that names it, not only the sets whose colour it was. Before, when a
  new texture took the destroyed one's handle, a set naming the destroyed
  view and sampler was handed out as current:
  `tests/test_backend_parity` drew 36 times through one.
- Measured under the Khronos layer with synchronization validation on:
  `test_fog` has 0 errors (was 3), `test_overlay` 0 (was 1) and
  `test_backend_parity` 0 (was 36).
- `ci.sh` runs those three suites under the layer, fails on any error it
  reports, and skips (never passes) where the loader did not insert it.
  The Linux job installs `vulkan-validationlayers`.
- CI's step restoring `contrib/vulkan/aether_vulkan.c` after the Aether
  install is removed. The installer keeps it since aether-lang-dev/aether#2208.
