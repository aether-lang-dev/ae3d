### Scenes in code: nesting is the hierarchy, and a saved scene is written as that code

- **`ae3d.scenedsl`** (#275): a scene written as trailing-block builders,
  each taking the block it is in as `_ctx`.
  - A model in a model's block is its child.
  - A light in a model's block is that model's own.
  - A component goes on the model whose block it is in, or on the scene's
    root; the camera is the scene's Camera component.
  - It builds what a scene file loads into: models, lights, attachments
    and components.
  - Records (a body, water, a voxel world, a figure, motion, a marker's
    light) are written in the file's own names and read by the file's own
    reader, so for those the DSL and the file agree by construction.
  - `scenedsl.place(e, s)` puts the scene into an engine.
  - A builder written where it means nothing, or a model whose file is
    gone, is counted and said, not crashed on.
- **The editor writes the code too.** Every Save writes `scene.ae` beside
  `scene.json`, made from the file just saved (`scenedsl.write_from_file`):
  a module whose `build()` is the scene.
- `examples/spinning_cube.ae` is written in it. Its Spinner is a schema
  kind, set by name from the scene.
- **The scene module, shared rather than copied.**
  - `scene.attachment_of` reads one entry's records. It is
    `scene_load_attachments`' loop body, now also the DSL's.
  - `scene.source_clone` and `scene.mesh_model` are `scene_load`'s two
    ways to make a model.
  - The material numbers are one table (see the scene-components change).
  - `core.look_angles` is `camera_look_at`'s yaw and pitch, for a Camera
    component written before there is a camera.
- `docs/scenes-in-code.md`: every builder, where each goes, `place`, and
  the written code.
- `test_scenedsl`, new: a scene of every builder is saved and loaded back
  as the same tree. Its file written as code must be the golden
  `tests/fixtures/scene/written`, which the test is built with, and that
  code builds the same tree again.
- **A scene with textures loaded after an engine was made waited for
  ever.** `core.preload_images` decoded on std.worker and joined with
  `worker.wait()`. That waits for every job the process ever launched,
  detached ones included, and the job pool's threads, made by
  `engine_new`, never end. The decodes now run on the engine's own pool
  (`geometry.run_blocks`), which joins exactly them, or on the calling
  thread where there is no pool. The editor and the agent load scenes
  with an engine made. A five-line program (`engine_new`, then a preload
  of one PNG) hung before and returns now. `test_scenedsl` makes an
  engine and then loads a textured scene.
- Found on the way: `s = scene { ... }`, without the parentheses, passes
  Aether's checker, binds `s` to the function, and runs the block with no
  context. The page says to write `scene()`, and the repro is drafted for
  Aether.
