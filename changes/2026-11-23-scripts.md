### Scripts: the struct is the declaration, every phase, contacts, spawns, a layout check

- **A kind read off its struct** (#508, aether#2298): `@derive(schema)` on a
  script's struct is its fields: their types, `@range`, `@default`, `@tooltip`,
  and `@transient`, `@readonly` and `@hidden`. `@enum(...)` and `@object` mark
  ints, `@color` a Vec3. The engine makes and frees the state, so a script is
  its struct and its phases, with no `create`, `destroy` or `fields`.
  - `component.schema_kind(name, category, T_schema())` reads any struct the
    same way, and `component.schema_fields` adds a schema's fields to a kind
    that keeps its own constructor. A struct holding a string is refused:
    only its own code can free it.
  - The four example scripts and the editor's New Script template are in this
    form.
- **Every phase.**
  - `on_enable` and `on_disable`, in Unity's order. Hot reload tells a running
    attachment `on_disable` by the old code and `on_enable` by the new.
  - `on_collision_enter`, `stay` and `exit`, with the object met, the point,
    the normal, the step's impulse and the closing speed.
  - `on_trigger_enter`, `stay` and `exit`.
  - `on_net_spawn`, on every peer, once each object is placed and its side
    known.
- **Triggers** (`trigger = true` on any convex collider), saved in the scene
  file. Characters walk through them and are told of them: the character's
  moves met trigger shapes as walls. Contacts are kept only for pairs a side
  listens to. The impulse is the step's whole, not the last sub-step's quarter
  of it.
  - The Physics Body component shows `trigger`, and the editor keeps it
    (`scene.physics_spec_copy`). The editor copied a body's record field by
    field, without the trigger, on save and on load, so a trigger came back
    from the editor as a wall.
- **The layout check.** Every script library exports the layout it was built
  against (`script_layout_hash`). The loader refuses a library with another
  layout, or none, naming both. Before, a script built from another tree
  misread every object it was handed.
- **`tools/new_game`** scaffolds a game repository with ae3d at `ext/ae3d`: a
  manifest, a program with physics, and a script. It builds with `ae build`
  and runs.
  - `scripts/build_script.sh` takes the caller's relative paths. They were
    read against the ae3d root.
  - A script built outside the tree finds the engine's library by its whole
    path.
- **Lookups.** `behaviour.object_find(go, name)`, and
  `component.state_of(go, kind)` and `component.state_named(go, name)`.
- `docs/scripting.md`: from an empty folder to a moving, tunable object, and
  every phase and attribute.
- Tests:
  - `test_script` 18 checks: schema scripts, and a stale and a foreign library
    refused.
  - `test_components` 139: the activation order, and a schema kind's every
    field type, defaults, ranges, save and load, and the string refusal.
  - `test_contacts` 22, new.
  - `test_net_spawn` 10, new.
  - Every one of them shows 0 leaks.
